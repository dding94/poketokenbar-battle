이메일은 표시값이다. 입력한 이메일을 실제로 소유하는지, 실제 회사 직원인지는 확인하지 않는다. 초대코드가 참여 범위를 정하고 개인 접속키가 소유자를 구분한다. 같은 이메일을 입력했다는 이유로 기존 계정이나 포켓몬에 접근시켜서는 안 된다.

신뢰 모델: 서버가 전투를 계산하지 않으므로, 앱을 개조한 사람은 숨긴 정보(상대 기술·특성)를 볼 수 있고 거짓 해시로 경기를 VOID로 만들 수 있다. 일치하는 두 보고 없이는 소유권이 움직이지 않으므로 남의 개체를 빼앗을 수는 없다. 로컬 육성 수치 위조를 첫 버전 범위 밖으로 둔 것과 같은 급의 위험으로 수용하고, 해시 불일치 횟수를 그룹에 공개해 억제한다.

- 타인에게 얻은 개체를 자동 졸업 처리해 `collectedFinals`와 기존 성장 보너스를 올리지 않는다.

### 사전 실측 (2026-10-29)

이 개정을 정하기 위한 조사 증거이며 PR 체크박스를 대신하지 않는다. 재현 가능한 테스트와 CI는 PR 01에서 저장소에 추가한다.

- 엔진: `@pkmn/sim` 0.10.12(Pokémon Showdown 시뮬레이터 추출본, MIT)를 esbuild 0.28.2로 단일 IIFE 번들로 만들었다. macOS 26.5의 Swift `JSContext`에서 보조 코드 없이 실행됐다.
- 결정성: `gen5customgame` 무작위 1:1 2,500판과 200턴 제한을 노린 장기전 200판을 Node 24.14.0과 JavaScriptCore(JIT 켬·끔)에서 실행했다. 정규화 로그(`|t:|` 줄 제외)·승자·inputLog 불일치는 0건이었다.
- 재생: inputLog만으로 다시 실행한 2,700판이 모두 같았다. 3턴 시점 상태 직렬화 왕복도 1,692판 모두 같은 결과였다.
- 성능: JavaScriptCore(JIT) 경기당 평균 1.2ms, 첫 실행은 번들 평가 약 200ms, 장기전 약 17ms였다. JIT가 없으면 경기당 약 7.8ms였다.
- 번들: 최소화 6.6MB(gzip 1.0MB). 미최소화 11.0MB 중 약 8.7MB가 전 세대 학습 기술 데이터로, 전투에는 필요 없을 것으로 보이나 제거는 검증하지 않았다.
- macOS 26.5에서 `JSContext`의 JIT는 `com.apple.security.cs.allow-jit` entitlement로 서명해야 켜졌다.
- 비결정 요소: `Date.now`는 `|t:|` 줄에만, `Math.random`은 seed를 주지 않을 때만 쓰인다.
- 주의: Showdown의 `BattleStream`은 `>eval` 명령을 받는다. 중계받은 텍스트를 스트림에 넣지 않고 검증한 선택 토큰만 `choose()`로 넘긴다. 숨은 정보 때문에 `choose()`가 거절될 수 있으며 거절도 결정적이다.
- 데이터 차이(`@pkmn/dex` 0.10.12, 9세대와 5세대 비교, 1~649번): 일반 특성 24종(그중 13종은 5세대에 없는 특성), 숨겨진 특성 23종, 타입 22종, 종족값 55종이 다르다. 9세대 규칙을 고른 근거다. Showdown 9세대 데이터는 PokéAPI 최신값의 대용이며 직접 대조는 PR 02에서 한다.
- 미검증: 9세대 규칙의 결정성·기술 동작, 다른 macOS 버전의 JavaScriptCore, 실제 두 맥 대전, 학습 기술 데이터 제거.
- 같은 날 저장소의 `engine/probe/`로 옮겨 다시 실행한 결과도 2,500판 불일치 0, 재생·상태 왕복 실패 0이었다. 단, 이름을 바꾸는 최소화 빌드에서는 상태 직렬화 왕복이 100판 중 65판 어긋났고 `--keep-names`로 해결됐다(재현: `engine/README.md`).

## 3. 첫 버전의 사용자 흐름

### 3.1 가입·등록

1. 방장이 회사 그룹을 만들고 만료·회수가 가능한 초대코드를 발급한다.
2. 동료는 코드와 이메일 표시명을 입력한다. 앱은 개인 접속키를 Keychain에 저장하고 복구코드를 보여 준다.
3. 원본 세이브를 보존한 뒤 현재 육성 중 개체와 졸업 개체를 서버에 등록한다.

### 3.2 배틀

1. 신청자가 상대, 경기 종류(쟁탈전·친선전), 배틀 방식(직접 조작·자동), 출전 개체를 고른다.
2. 상대는 신청자 개체의 공개 정보(종·레벨·타입·능력치)와 조건을 보고 자기 개체를 골라 수락하거나 거절한다. 신청자는 상대 개체의 공개 정보를 확인하고 확정한다. 상대를 정하기 전에 한 동의는 최종 동의로 보지 않는다.
3. 시작하려면 양쪽 앱이 같은 엔진 해시로 연결되어 있어야 한다. 직접 조작은 양쪽 사람이, 자동은 양쪽 앱만 있으면 된다. 앱이 꺼져 있으면 도전 만료 안에서 기다린다.
4. 서버가 두 개체를 잠그고 시작 시점의 전투 스냅샷, seed, 규칙·엔진·정책 버전을 고정한다.
5. 직접 조작: 매 턴 양쪽이 제한시간 안에 기술을 고르고, 서버는 둘 다 받은 뒤 동시에 공개한다. 시간 초과·연결 끊김 턴은 자동 선택 정책이 고른다. 자동: 모든 턴을 정책이 고른다.
6. 양쪽 앱이 같은 턴을 계산해 같은 화면을 보여 준다. 재접속하면 입력 기록 재생으로 같은 장면을 복원한다.
7. 종료 후 양쪽 앱이 승자와 결과 해시를 보고한다. 일치하면 서버가 결과·이전·스타터 권리를 한 트랜잭션으로 확정하고, 불일치면 VOID로 끝낸다.
8. 승자는 획득 개체를 보유 목록에서 선택해 육성을 이어갈 수 있다. 마지막 개체를 잃은 사용자는 쿨다운에 맞춰 새 스타터 한 마리를 고른다.
9. 쟁탈전 패자는 24시간 안에 같은 상대에게 리벤지 매치를 한 번 신청할 수 있다.

같은 그룹 동료는 진행 중인 배틀을 관전할 수 있다. 관전자 앱도 같은 선택 기록을 받아 직접 재생한다.

### 반드시 유지할 조건

- 한 개체에는 현재 소유자가 한 명만 있다.
- 한 개체는 동시에 한 경기에서만 잠길 수 있다.
- 다른 그룹의 계정·포켓몬·경기 ID를 알아도 조회·변경 권한이 생기지 않는다.
- 출전·성장 동기화·이전 판단에는 종 ID·이메일·UI ID가 아닌 서버 사용자·개체 ID를 사용한다.
- 같은 경기의 결과와 이전은 한 번만, 양쪽 보고 해시가 일치할 때만 확정한다.
- 서버는 두 선택을 모두 받기 전에는 어느 쪽 선택도 공개하지 않는다.
- 중계는 선택 토큰(`move 1`~`move 4`, 필요한 경우 `team 1`)만 통과시킨다. 앱은 중계받은 텍스트를 시뮬레이터 스트림에 넣지 않는다.
- 양쪽 엔진 해시가 다르면 경기를 시작하지 않는다.
- 마지막 개체 상실로 생긴 스타터 권리는 같은 원인에 대해 한 번만 생성·사용되고 쿨다운을 지킨다.
- 도감 이력이 남아 있다는 이유로 패배·놓아줌·동결 개체를 출전시킬 수 없다.
- 상세 로그 정리와 관계없이 결과 요약, 입력 기록, 소유권 이전, 지급 중복 방지 근거는 유지한다.
- 사용자가 수정한 UUID로 복제한 개체와 조작한 로컬 성장 이력까지 증명하는 부정 방지는 첫 버전 범위 밖이다.

## 6. 세부 정책

### 6.1 초대·개인 접속키·복구

- 방장만 코드 발급·회수·멤버 제한·재연결 코드 발급을 할 수 있다. 코드에는 만료와 사용 한도를 둔다.
- 접속키는 충분한 엔트로피의 난수로 발급한다. 서버에는 SHA-256/HMAC 해시만 저장한다. 느린 KDF는 무료 CPU 한도를 넘기므로 쓰지 않는다.
- Keychain 항목은 환경(개발·운영)과 상태 폴더별 프로필 ID로 구분해 `PTB_STATE_DIR` fixture끼리 충돌하지 않게 한다. `disableKeychainAccess` 설정을 배틀 키에도 적용할지는 PR 07에서 정한다. 세이브 내보내기에는 키를 넣지 않는다.
- 초대코드 자체를 이후 API의 인증키로 재사용하지 않는다.
- 이메일 중복 입력을 기존 계정 로그인으로 처리하지 않는다. 같은 그룹의 중복 표시명은 안내하고 기존 계정 복구로 연결한다.
- 초기 가입 때 복구코드를 제공한다. 복구 시 기존 접속키를 폐기하고 복구코드도 교체한다.
- 방장 보조 재연결: 방장이 특정 계정 전용 일회용 재연결 코드를 발급한다. 사용하면 기존 접속키·복구코드를 폐기하고 그 기록을 그룹에 남긴다.
- 초대·복구·재연결 코드 입력은 시도 횟수를 제한한다.
- 접속키·복구코드·초대코드·재연결 코드는 앱 로그, URL, 분석 이벤트에 남기지 않는다.
- 계정 복구와 무관하게 서버의 사용자 ID와 개체 소유권은 유지한다.

### 6.2 기존 데이터 등록·로컬 성장

- 원본 세이브의 백업과 schema version을 먼저 확보하고 개발용 복사본에서 검증한다.
- 초기 등록 대상은 현재 육성 중 개체와 놓아주지 않은 졸업 개체다. 도감의 진화 단계 이력을 별개 포켓몬으로 복제하지 않는다.
- 초기 등록은 재시도 가능하게 만들며 원본 instanceID의 중복·이전 소유권을 서버에서 확인한다.
- 새로 부화한 개체와 성장 데이터도 동기화한다. AI 사용 로그·프롬프트·회사 코드·원본 토큰 로그는 전송하지 않는다.
- 전투 스냅샷(종·폼·레벨·IV·성격·특성·기술·성별)과 성장 진행도(growthTokens·usedAtStage)를 별도 버전으로 관리한다. 성장 진행도만 바뀐 동기화는 동의를 무효로 만들지 않는다.
- 성장 수치는 신뢰하되 레벨·IV 범위·종·기술·특성 유효성은 검증하고 능력치는 엔진이 계산한다.
- `ownershipVersion`이 다른 오래된 소유자의 동기화는 거절한다. 낮은 버전의 늦게 도착한 응답이 새 상태를 덮지 못하게 한다.
- 오프라인에서 등록 개체를 키울 수 있지만 재연결 시 서버 소유권이 먼저다. 다른 사람에게 이전된 개체의 오프라인 성장분을 새 소유자에게 덮어쓰지 않는다.
- 경기 중 개체는 다른 출전·놓아주기를 잠그고 성장 반영을 보류한다. 소유권이 유지되면 보류분을 반영하고, 이전됐다면 이전 소유자의 쓰기를 차단한다.
- 원본 앱이나 수정한 클라이언트가 로컬에 개체를 표시하는 것까지 막는다는 의미는 아니다. 온라인 소유·출전·이전은 서버 기록을 따른다.

### 6.3 전투 입력·규칙·정보 공개

- 종·폼, 레벨, IV, 성격, 특성, 성별, 현재 기술을 엔진 입력으로 정규화한다. 이로치 여부는 전투 능력치에 영향을 주지 않는다.
- 9세대 규칙을 쓰고 테라스탈은 금지한다. 지닌 도구는 없음, EV는 0으로 고정한다. 체력·PP는 매 경기 정상 상태로 시작하고 전투 피해를 육성 상태에 남기지 않는다.
- 종족값·타입·특성은 9세대 데이터를 쓴다. PokéAPI 최신값과 차이가 남으면 출전 화면에 실제 적용 값을 보여 준다.
- 기존에 배운 최대 4개 기술을 유지한다. 기술 편집 UI는 첫 버전에서 추가하지 않는다.
- 지원하지 않는 폼·잘못된 기술·매핑할 수 없는 특성을 조용히 기본값으로 바꾸지 않는다. 등록 자료는 보존하고 출전을 보류하며 이유를 표시한다.
- 출전 전 공개 정보는 종·레벨·타입·능력치다. 기술·특성은 배틀 로그에서 처음 쓰이거나 드러날 때 공개한다. 이 숨김은 정상 앱의 표시 규칙이며 보안 경계가 아니다.
- 자동 선택 정책은 양쪽에 같다. 사용 가능 기술·명중·상성·피해 기대값과 정해진 보조기 조건을 평가하고 동률은 전용 seed 난수로 정한다. 별도 LLM 호출이나 유료 AI 서비스는 쓰지 않는다. 정책 버전을 저장한다.
- 상태이상, 우선도, 반동, 회복, 면역, 날씨, PP 소진 등은 엔진 규칙을 따른다.
- 200턴에 도달하면 무승부로 끝낸다(어댑터가 강제). 엔진 자체 1000턴 한도에 의존하지 않는다.

### 6.4 도전·배틀 방·확정

- 상태 흐름: `PENDING → ACCEPTED → READY → RUNNING → REPORTED → COMPLETED`.
- 확정 전 종료: `DECLINED`, `CANCELLED`, `EXPIRED`. 결과를 확정할 수 없는 경기: `VOID`.
- `PENDING`에서 출전 개체가 바뀌면 동의 revision을 올리고 기존 동의를 무효화한다. 성장 진행도 변화는 무효 사유가 아니다.
- 양쪽 앱이 연결되어 `READY`가 되는 순간 소유자·잠금·엔진 해시를 확인하고 두 개체 잠금, 전투 스냅샷, seed, 규칙·엔진·정책 버전을 한 트랜잭션으로 저장한다.
- 미확정 도전은 24시간 뒤 만료한다(제안 기본값). 수락·취소 경합과 중복 클릭은 DO의 직렬 처리와 멱등 키로 하나의 전이만 성공시킨다.
- 직접 조작 턴 제한시간은 30초(제안 기본값)다. 시간 초과·연결 끊김 턴은 자동 정책을 쓰며 양쪽 앱이 같은 선택을 계산한다.
- 재접속한 앱은 저장된 seed·스냅샷·선택 기록을 재생해 같은 장면으로 복원한다.
- 종료 후 양쪽 앱이 승자와 정규화 로그 해시를 보고한다. 일치하면 확정하고, 불일치면 VOID로 끝내며 불일치 기록을 그룹에 공개한다.
- 한쪽 보고가 없으면 그 앱이 다음 접속 때 자동으로 재생·보고한다. 기한(제안 72시간) 안에 보고가 없으면 VOID로 끝낸다.
- 서버 배포로 모든 연결이 끊겨도 방 상태는 DO 저장소에 남아 재접속 후 이어진다. 엔진 해시가 다른 앱 업데이트가 진행 중 경기에 끼어들면 같은 엔진으로 마치거나 VOID로 끝낸다. 다른 엔진 버전으로 조용히 재계산하지 않는다.

### 6.5 결과·소유권 이전·스타터·연승

- 확정은 League DO의 `transactionSync()` 하나에서 결과, 이전 원장, 현재 owner, ownershipVersion 증가, 잠금 해제, 승자 도감 획득 이력, 연승, 필요 시 스타터 권리를 함께 처리한다.
- 확정 응답이 유실되면 같은 경기 조회·재시도에서 저장한 결과를 반환한다.
- 같은 종이 이미 있어도 승자의 기존 개체를 덮어쓰지 않는다. 획득 개체의 ID·성장 데이터·성격·폼·이로치·진화 상태를 유지한다.
- 이력과 실제 보유를 분리한다. 패자는 과거 도감 기록을 유지하되 출전·육성 대상에서 해당 개체를 제외한다.
- 친선전은 이전·스타터 권리·연승에 반영하지 않는다. 친선전 전적은 별도로 표시한다(제안).
- 스타터 권리는 쟁탈전 결과로 서버 보유 개체가 0이 된 전이에서 생성한다. 첫 가입·미등록 상태는 전멸이 아니다.
- 스타터 선택은 직전 스타터 지급 후 3일이 지나야 가능하다. 첫 지급은 즉시다. 선택할 때 보유 상태·권리 미사용·쿨다운을 다시 확인하고, 중복 요청에는 같은 지급 결과를 반환한다.
- 스타터는 서버에서 새 ID와 유효한 프로필을 생성한다. 기존 알은 삭제하지 않는다. 활성 개체 변경은 기존 육성 상태를 보존하는 절차로 처리한다.
- 무승부·VOID는 소유권·스타터 권리·연승을 바꾸지 않는다.
- 연승은 쟁탈전 승리로 늘고 패배로 끝난다. 그룹에서 현재 연승이 가장 긴 사람을 챔피언으로 표시한다(제안 규칙).
- 리벤지 매치: 쟁탈전 패자가 24시간 안에 같은 상대에게 한 번 신청할 수 있고 승자가 수락해야 성립한다. 승자가 거는 개체를 방금 얻은 개체로 고정할지는 PR 12에서 정한다(제안: 고정).
- 무료 한도나 일시 장애에서는 미확정 결과를 표시하지 않고 보류한다. 복구할 수 없는 경기만 VOID로 처리해 잠금을 해제한다.

### 6.6 기록·관전·보관

- 경기마다 전투 스냅샷, seed, 선택 기록, 엔진·규칙·정책 버전, 양쪽 결과 해시를 저장한다. 경기당 수 KB다.
- 기록 재생은 저장한 입력을 같은 엔진 버전으로 다시 계산해 보여 준다. 엔진이 바뀐 뒤 과거 경기를 어떻게 재생할지(구버전 엔진 보관 또는 상세 로그 저장)는 PR 11에서 정한다. 과거 경기를 최신 엔진으로 다시 계산해 결과를 바꾸지 않는다.
- 한국어 기술명·상태 메시지를 매핑하고, 미번역 이벤트는 누락하지 말고 읽을 수 있는 대체 표시를 제공한다.
- 관전은 같은 그룹만 가능하다. 관전자 앱이 선택 기록을 받아 직접 재생하며 정보 공개 규칙을 똑같이 적용한다.
- 결과를 확인할 수 있는 그룹 범위를 검사한다. 외부 공개 링크는 첫 버전 범위 밖이다.
- 선택적 상세 로그는 90일 후 정리하고 승패·입력 기록·소유권 요약은 유지한다.

### 6.7 탈퇴·퇴사

- 본인 탈퇴나 방장 제거 시 접속키를 폐기하고 개체를 동결한다. 동결 개체는 소유권을 유지하지만 출전·이전·리벤지 대상이 될 수 없다.
- 표시명은 '떠난 트레이너'로 익명화한다. 승패·이전 기록은 서버 ID로 유지한다.
- 다시 합류한 동료의 동결 해제는 방장이 처리한다(제안).

### 운영 중 제한 처리

- 키·IP별 요청 제한과 경기 수 상한을 두고, 앱은 오류 시 지수 백오프한다. 팝오버가 닫혀 있으면 연결만 유지하고 주기 조회를 하지 않는다.
- 무료 한도를 넘으면 오류·보류로 처리하고 리셋까지 신규 경기 접수를 멈춘다. 유료 플랜 자동 전환, 유료 외부 API, 새 유료 서비스는 추가하지 않는다.
- 저장 공간 경고·접수 제한 기준은 실측 후 보수적으로 정한다.
- 백업: 방장 앱이 원장 내보내기를 주기적으로 받아 로컬에 보관한다. DO 시점 복구(30일)의 무료 적용 여부는 PR 05에서 확인한다.
- 단순 앱 내 사용량 추정은 Cloudflare 계정 전체 한도를 대신하지 않는다. 대시보드 실제 사용량과 함께 확인한다.
- 무료 운영 검증에 실패하면 기능 확대를 멈추고 대안(예: Supabase Free)을 사용자와 다시 결정한다.

## 9. 검증 명령과 증거

아래 명령은 **향후 구현 시 실행할 계획**이다. 이번 계획서 작성에서 실행하거나 통과한 명령이 아니다.

### PokeTokenBar 포크

기존 `Package.swift`와 `scripts/test-gate.sh`에서 확인한 명령:

```sh
swift test --filter <변경한 테스트 묶음>
swift build
./scripts/test-gate.sh
```

대상 테스트는 기존 `Tests/PokeTokenBarTests/`의 관례에 맞춘다. 최종 게이트는 전체 Swift 테스트와 기존 코어 커버리지를 확인한다. 커버리지 비율만으로 통과시키지 않고 실제 변경한 실패 분기의 실행을 확인한다. UI 검증은 분리한 저장소로 실행하고 실제 화면 증거를 남긴다.

### 새 `engine/`·`server/`의 제안 스크립트

다음 이름은 현재 존재하는 명령이 아니라 PR 01·04~06에서 정의할 검증 인터페이스다.

```sh
# engine/
npm run build      # 단일 번들 생성과 번들 해시 출력
npm test           # 어댑터·정책 단위 테스트
npm run corpus     # Node와 JavaScriptCore 결정성 코퍼스

# server/
npm run typecheck
npm test           # Workers 런타임 단위·통합 테스트
npm run test:acceptance
```

- 단위: 입력 정규화·기술 선택·상태 전이·결과·지급 정책.
- 결정성: 같은 코퍼스를 Node와 JavaScriptCore에서 실행해 정규화 로그·승자·inputLog를 비교한다. macOS 버전별 결과는 CI 러너로 확인한다.
- 통합: Workers 실행 환경, DO 바인딩·WebSocket·알람·트랜잭션·동시성.
- 인수: 두 사용자 전체 흐름과 장애·복구. 실제 사용자 키나 운영 개체를 테스트 fixture로 사용하지 않는다.
- 성능: 실제 Cloudflare Free 환경의 메시지 CPU·요청·행·연결 수. 테스트 횟수와 환경을 기록한다.
- 증거에는 마지막 관련 변경 이후의 명령·종료 코드·실행 테스트 수·실패/skip·측정값을 포함한다. 테스트 0건, 전부 skipped, 로컬 측정만 있는 상태를 배포 검증 성공으로 보고하지 않는다.

## 10. 필수 인수 시나리오

- [ ] 두 맥이 로그인 화면 없이 초대코드·이메일 표시명으로 같은 그룹에 참여한다.
- [ ] 잘못된 코드·회수 코드·다른 그룹 키로 참가자 데이터에 접근할 수 없다.
- [ ] 같은 종의 서로 다른 개체를 각각 선택할 수 있고 놓아준·동결된 개체는 선택할 수 없다.
- [ ] 신청 때 정한 경기 종류·배틀 방식과 양쪽 개체에 동의한 경우에만 경기가 시작된다.
- [ ] 출전 개체가 바뀌면 이전 동의를 재사용하지 않고, 성장 진행도만 바뀌면 동의가 유지된다.
- [ ] 출전 전에는 종·레벨·타입·능력치만 보이고 기술·특성은 처음 쓰일 때 공개된다.
- [ ] 직접 조작에서 먼저 고른 쪽의 선택이 상대보다 먼저 공개되지 않는다.
- [ ] 시간 초과·연결 끊김 턴은 자동 정책으로 진행되고, 재접속하면 같은 장면으로 복원된다.
- [ ] 두 맥이 같은 결과 해시를 보고하고, 해시가 다르면 이전 없이 VOID로 끝난다.
- [ ] 레벨·IV·성격·특성·기술·타입이 결과와 로그에 반영된다(9세대 규칙, 테라스탈 없음).
- [ ] 쟁탈전 승자는 패자의 정확한 한 개체를 얻고 패자는 그 개체를 출전·육성할 수 없다. 친선전은 아무것도 이전하지 않는다.
- [ ] 승자의 동일 종 기존 개체와 과거 도감 이력이 손상되지 않는다.
- [ ] 획득한 미성숙 개체의 진화·성장을 이어갈 수 있다.
- [ ] 수락·확정 재시도와 응답 유실에도 한 경기·한 이전만 남는다.
- [ ] 실행 중 앱 종료·서버 배포에도 결과를 복구하거나 이전 없는 VOID로 끝난다.
- [ ] 동시 수락·다른 경기 출전·취소 경합으로 부분 잠금이나 이중 소유가 생기지 않는다.
- [ ] 세이브 복원과 오래된 성장 업로드로 이전된 개체를 되찾지 못한다.
- [ ] 마지막 개체 상실 후 선택한 Lv5 스타터가 한 번만 지급되고 3일 쿨다운이 지켜진다.
- [ ] 방장 보조 재연결 후 이전 키·복구코드가 거절된다.
- [ ] 탈퇴한 동료의 개체는 동결되고 표시명은 익명화되며 기록은 남는다.
- [ ] 관전자가 같은 진행을 보고 정보 공개 규칙이 관전에도 적용된다.
- [ ] 연승·챔피언은 쟁탈전 결과로만 바뀌고 리벤지 매치는 24시간 안에 한 번만 신청된다.
- [ ] 무승부·오류·무료 한도 보류에서 개체나 스타터가 임의로 이동·생성되지 않는다.
- [ ] 백업 복구 후 두 계정의 소유 목록·결과·이전 이력이 일치한다.
- [ ] 최종 사용량이 무료 한도와 운영 여유 범위에 들어오며 유료 의존성이 없다.

## 부록 A. 전투 엔진 API 계약 (PR 01 초안)

앱은 `JSContext`에 번들 하나를 올리고 전역 `PTBEngine`을 동기적으로 호출한다. 인자와 반환값은 JSON 문자열이며, 경계를 넘어 예외를 던지지 않고 `{"ok":false,"error":"..."}`로 돌려준다. 구현 중 계약을 바꿔야 하면 이 부록을 먼저 고친다.

| 호출 | 내용 |
|---|---|
| `version()` | `{"engine":"@pkmn/sim@x.y.z","adapter":"1","rules":"gen9-notera-noitems-v1"}` |
| `describeSet(set)` | 검증한 SET의 공개 정보 `{speciesNum,species,level,types,stats}`. 9세대 폼/EV 0 능력치를 계산하며 기술·특성은 반환하지 않음(PR 02 추가) |
| `createBattle(config)` | config = `{"seed","policySeed","p1":{"name","set":SET},"p2":{...}}` → `{"ok":true,"id"}`. 알 수 없는 종·폼·기술·특성은 오류 코드로 거절 |
| `request(id, side)` | `{"kind":"move"·"wait"·"forced"·"none","moves":[{"slot","id","name","type","pp","maxpp","disabled"}]}` |
| `choose(id, side, choice)` | choice = `{"type":"move","slot":1~4}` 또는 `{"type":"auto"}` → `{"ok":true,"resolved":bool}`. Showdown 거절은 `{"ok":false,"error":"rejected"}`(결정적). 그 밖의 입력은 거절 |
| `autoChoice(id, side)` | `{"slot":n}`, 적용하지 않음 |
| `state(id, viewer)` | viewer = `p1`·`p2`·`spectator`. 양쪽 VIEW: 종·레벨·타입·HP는 항상, 상대 기술은 이미 쓴 것만, 특성은 로그로 드러난 뒤에만 |
| `drainEvents(id, viewer)` | viewer별 최초 기술·특성 공개 이벤트 `{kind,side,id,turn}` 배열(PR 03 추가). 중복 없이 별도 커서로 읽음 |
| `drainLog(id, viewer)` | 그 viewer가 볼 새 프로토콜 줄. 상대의 정확한 HP를 노출하지 않고 `|t:|` 줄을 뺀다 |
| `result(id)` | `{"ended","winner","turns","logHash","inputLog"}`. logHash = `|t:|`를 뺀 전체 로그의 SHA-256 |
| `replay(inputLog)` | 입력 기록으로 다시 실행해 `{"winner","logHash"}`. 검증한 선택 토큰으로 다시 구성하며 `>eval` 같은 스트림 명령을 통과시키지 않는다 |
| `destroy(id)` | 정리 |

SET = `{"speciesNum","form"(앱 PokemonForm 원시값 또는 null),"level","gender":"male"·"female"·"genderless","nature"(소문자),"ability"(PokéAPI slug),"moves"(PokéAPI slug 1~4개),"ivs":{"hp","attack","defense","special-attack","special-defense","speed"},"shiny"}`. slug에서 Showdown id로의 변환은 영숫자만 남기는 것이 기본이며, 실제 데이터에서 어긋나는 것은 별칭 표로 고정한다.

inputLog v2 = `{version:2,policyVersion:"auto-v1",config,choices:[{side,choice}]}`. 이전 버전/정책 기록은 명시적 오류로 거절하며 조용히 새 정책으로 해석하지 않는다.

규칙: 9세대, 테라스탈 금지, 도구 없음, EV 0, 200턴 무승부(어댑터가 강제), 팀 미리보기와 강제 행동(재충전·발버둥)은 어댑터가 처리한다.

폼: 외형만 다른 폼은 기본 폼으로, 배틀 중에만 바뀌는 폼(캐스퐁 날씨 폼, 체리꼬 포지폼, 불비달마 달마모드, 메로엣타 스텝폼)은 기본 폼으로 시작한다. 도구가 필요한 폼(아르세우스 타입, 기라티나 오리진폼, 게노세크트 카세트)은 도구 없는 규칙에서의 동작을 정해 테스트로 고정하고, VIEW에 실제 전투 폼을 보인다.

자동 정책 v1(PR 03에서 확정): 공격기는 위력 × 자속 보정 × 상성(무효면 0) × 명중/100으로 평가한다. 보조기는 효과가 아직 없을 때만 낮은 고정 점수를 주고 능력 상승은 +2까지만 쓴다. 동률은 policySeed·턴·진영으로 만든 전용 난수로 정한다.

이 문서는 승인한 설계와 향후 실행할 체크리스트다. 체크박스는 실제 작업과 검증 증거가 생긴 뒤 갱신한다. 구현은 별도의 착수 지시 후 진행한다.
